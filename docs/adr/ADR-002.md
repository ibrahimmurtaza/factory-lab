# ADR-002: CLI-first product interface

## Context

The initial interface must be a CLI, with a web dashboard planned for the future. The framework must not couple orchestration logic to any specific interface.

## Decision

The initial user interface is a CLI built with Python. The CLI is a thin entry point that delegates to control-plane services; it contains no orchestration logic. A future web dashboard or API layer can be added as a separate entry point using the same services.

## Alternatives

1. **CLI-first (chosen)** — Matches the product direction; minimal dependencies; easy to script and integrate.
2. **API-first with CLI as client** — Premature; requires server infra before local value.
3. **Web dashboard first** — Contradicts the stated initial interface; requires frontend tooling.

## Consequences

Positive:
- Fast to build and test locally.
- Natural fit for developer tools and CI invocation.
- Interface logic separated from business logic, enabling a future API/dashboard.

Negative:
- No graphical interface initially; users must be comfortable with a terminal.
- Future API layer must share the same service layer to avoid duplicated logic.

## Status

Accepted — confirmed product requirement.
