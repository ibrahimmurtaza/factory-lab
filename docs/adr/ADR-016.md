# ADR-016: Execution Recovery, Persistence and Observability

## Context

OpenCode can fail halfway through a task; Factory Lab itself can crash while OpenCode is running. Execution output, partial changes, and failure context must be preserved for inspection. M7 defers database persistence; local JSON files are used until then.

## Decision

Persist execution records as JSON sidecars under `~/.factory-lab/executions/<exec-id>.json` following the M4 `JsonTaskStorage` pattern (atomic writes, schema versioning). Each execution gets a directory `~/.factory-lab/executions/<exec-id>/` with `logs/`, `artifacts/`, and `test-results/` subdirectories, preserving partial output on failure. On interruption (Ctrl+C), Factory Lab attempts graceful subprocess termination and marks the execution `failed` with an interruption reason. If Factory Lab crashes while OpenCode is running, the OpenCode process may be orphaned and the execution record remains in `running`; no automatic reconciliation or resume is performed — the user manually marks it `failed` or replans. `paused` means awaiting a Factory Lab-controlled checkpoint (pre-dispatch approval); it never implies suspend/resume of a running process.

## Alternatives

1. **Auto-reconcile `running` executions on restart (rejected)** — Cannot reliably detect orphaned processes; adds complexity not justified for M5.
2. **Resume failed execution from last step (rejected)** — M5 adopts abort-on-failure; replanning from a new approved revision is simpler and safer.
3. **Database persistence in M5 (rejected)** — M7 defers databases; JSON sidecars match M4's storage pattern.

## Consequences

Positive:

- Failed executions preserve worktree, logs, artifacts, and partial changes for inspection.
- Crash recovery is explicit and manual; no false resume semantics.
- Persistence follows the established M4 JSON sidecar pattern, replaceable at M7.

Negative:

- Orphaned OpenCode processes possible after a Factory Lab crash.
- No resume; users replan after failure, which may repeat work.

## Status

Accepted — M5 recovery, persistence, and observability model.
