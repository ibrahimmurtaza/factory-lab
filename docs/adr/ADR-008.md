# ADR-008: Deterministic Hybrid Implementation Planning

## Context

M4 needs to generate structured implementation plans from task descriptions and M3 `ProjectProfile` data. Model provider integration (OpenRouter) is deferred to a later milestone per AGENTS.md "no premature abstractions" and ADR-005 "interface kept minimal until a second implementation is concrete." The planner must be deterministic, evidence-based, and safe — it must not invent repository details or claim certainty where evidence is insufficient.

## Decision

`DeterministicTaskPlanner` implements a hybrid approach: a generic implementation-plan skeleton plus evidence-based technology-specific overlays. It accepts a task description and M3 `ProjectProfile`, and produces an `ImplementationPlan` with objectives, requirements, assumptions, unresolved questions, implementation steps, affected components, dependencies, acceptance criteria, testing strategy, risks, and evidence. Detected facts are distinguished from assumptions and unresolved questions. No `ModelProvider`, OpenRouter integration, API-key handling, or network dependencies in M4.

## Alternatives

1. **Hybrid deterministic planning (chosen)** — No model dependency, fully testable, evidence-gated tech overlays, explicit uncertainty handling.
2. **Model-driven planning in M4** — Requires `ModelProvider` interface, API keys, network access; contradicts "keep code execution and autonomous implementation outside M4" and AGENTS.md premature abstraction rules.
3. **Pure generic template with no tech awareness** — Loses value of M3 project intelligence; cannot reference detected frameworks or repository structure.
4. **Full rule engine / plugin framework** — Premature abstraction; no second implementation planned.

## Consequences

Positive:
- Deterministic: same inputs produce equivalent plan output.
- Fully unit-testable without mocks or network.
- Evidence-based: repository-specific claims supported by M3 inspection data.
- Safe: no invented paths, packages, versions, or test commands.
- `TaskPlanner` contract suitable for future AI-powered implementation.

Negative:
- Limited semantic interpretation of natural-language requests; sophisticated planning deferred to a later milestone.
- Tech overlays are a small initial set; not comprehensive.

## Status

Accepted — required for M4 deterministic planning.
