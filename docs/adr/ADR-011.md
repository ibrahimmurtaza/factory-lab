# ADR-011: Execution Records and Lifecycle

## Context

M4's `TaskStatus` enum has no execution states (running, completed, failed, paused). Modifying M4 models would break backward compatibility, serialization, and existing tests. M5 needs to track execution attempts independently of task approval state, support multiple attempts per task, and preserve M4's `approved` task status during execution. M7 defers database persistence, so execution records use local JSON sidecars until then.

## Decision

Introduce a parallel `ExecutionRecord` domain model persisted as JSON sidecars under `~/.factory-lab/executions/<exec-id>.json`, one per execution attempt, linked to `task_id` and referencing the exact approved plan revision. The `TaskRecord` and `TaskStatus` remain unchanged; a task stays `approved` during execution. Execution lifecycle: `queued → running → completed`, with alternatives `failed` (OpenCode non-zero exit or interruption) and `paused` (Factory Lab-controlled checkpoint awaiting pre-dispatch approval only; no suspend/resume of a running process). Multiple attempts are retained per task; `factory task status` shows the latest attempt while historical attempts remain accessible via a dedicated execution listing surface.

## Alternatives

1. **Extend `TaskStatus` with execution states (rejected)** — Would modify M4 `task_models.py`, breaking backward compatibility, serialization, and existing tests.
2. **Single execution record per task (rejected)** — Loses audit history; cannot compare attempts or preserve failed executions.
3. **Auto-resume failed executions (rejected)** — M5 adopts abort-on-failure; users replan from a new approved revision rather than resuming a terminated process.

## Consequences

Positive:

- M4 models and `TaskStatus` remain backward-compatible and untouched.
- Complete audit trail of execution attempts, each tied to a specific plan revision.
- Task status remains meaningful (approval state) while execution status is tracked separately.

Negative:

- Two status concepts (task vs execution) must be surfaced clearly in CLI output.
- Execution records grow with each attempt (acceptable for Phase 1 scale).

## Status

Accepted — M5 execution lifecycle foundation.
