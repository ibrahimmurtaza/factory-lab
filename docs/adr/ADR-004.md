# ADR-004: Modular monolith architecture

## Context

Factory Lab needs clear component boundaries now, but distributed microservices would be premature infrastructure for a single-team tool. The architecture should be a single codebase with well-separated packages that can evolve independently.

## Decision

Factory Lab is a modular monolith: one Python codebase with package boundaries separating CLI, control plane, execution plane, config, and errors. Components communicate via in-process calls and interfaces; no inter-service network boundaries are introduced in Phase 1.

## Alternatives

1. **Modular monolith (chosen)** — Simple deployment, clear boundaries, no operational overhead; boundaries can become service boundaries later.
2. **Microservices** — Premature; requires service discovery, networking, deployment orchestration.
3. **Big ball of mud** — Fastest initially but contradicts the requirement for clearly defined component boundaries.

## Consequences

Positive:
- Single deployable unit; simple local development.
- Clear package boundaries match the control/execution plane split.
- Components can be extracted to services later if scaling demands it.

Negative:
- Requires disciplined module boundaries to prevent coupling creep.
- All components share one process and one codebase.

## Status

Accepted — confirmed architecture style.
