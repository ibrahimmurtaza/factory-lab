# ADR-001: Local-first, cloud-capable deployment strategy

## Context

Factory Lab must run locally from day one while remaining architecturally capable of moving to cloud execution with centralized management later. The product direction explicitly requires local-first deployment with a long-term cloud goal.

## Decision

Factory Lab is local-first and cloud-capable. Phase 1 executes on the user's local machine in a local workspace. The execution environment is abstracted behind an interface so Docker containers and remote cloud workers can be adopted later without changing orchestration logic.

## Alternatives

1. **Cloud-first from the start** — Requires infrastructure (containers, queues, auth) before any local value is delivered; violates "avoid premature infrastructure."
2. **Local-only, cloud never** — Does not meet the stated long-term deployment goal; forces a rewrite later.
3. **Local-first with abstracted execution environment (chosen)** — Delivers immediate local value while keeping the cloud path open via interface boundaries.

## Consequences

Positive:
- Immediate local usability with no infrastructure setup.
- Cloud migration is an interface implementation, not an architectural rewrite.
- Execution isolation can be introduced incrementally (workspaces → worktrees → containers → cloud workers).

Negative:
- Abstraction layer adds modest indirection before any cloud implementation exists.
- Some cloud-specific concerns (auth, secrets, networking) are deferred and may require interface evolution.

## Status

Accepted — confirmed product requirement.
