# ADR-015: Execution Delivery and Cleanup

## Context

Completed execution work must reach the original repository without automatic merge or PR creation (GitHub PR is out of scope per ARCHITECTURE.md). Worktrees and execution data must be cleanable without discarding failed work accidentally. Delivery commits worktree changes and transfers them into a feature branch in the original repository; cherry-picking versus patch application is an implementation detail to investigate.

## Decision

`factory task deliver <exec-id>` transfers reviewed execution changes into a feature branch in the original repository (e.g., `factory-lab/<task-id>/<exec-id>`), applying worktree commits via patch or cherry-pick. Delivery refuses if the original working tree is dirty or the target branch already exists; the user confirms each delivery and decides whether to merge or open a PR manually. `factory task cleanup <exec-id>` refuses to remove a worktree with uncommitted changes or a non-terminal execution state unless `--force` is supplied. Execution JSON sidecars and per-execution artifacts (`logs/`, `artifacts/`, `test-results/`) are retained independently and removed only by explicit user action.

## Alternatives

1. **Auto-merge delivery into the original branch (rejected)** — Violates human review before delivery; no PR support in M5.
2. **No delivery surface; user copies manually (rejected)** — Leaves transfer to an unrecorded, unreviewable manual step.
3. **Automatic cleanup of old worktrees (rejected)** — Risks discarding the only copy of failed work before user inspection.

## Consequences

Positive:

- Delivery is explicit, reviewable, and recorded as a feature branch.
- Cleanup refusal protects failed and uncommitted work from accidental loss.
- Artifacts and execution records outlive worktree cleanup for audit.

Negative:

- Delivery conflicts (dirty tree, existing branch) require manual resolution.
- Worktree and artifact cleanup is manual; disk usage grows until cleaned.

## Status

Accepted — M5 delivery and cleanup model.
